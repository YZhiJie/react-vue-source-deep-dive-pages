## 登场角色

- **阿V**：Vue 绿餐厅的主厨兼老板娘，绿发少女，这一话带阿R 参观自家后厨。
- **阿R**：React 餐厅的服务员，来这里「偷师」，全程一脸惊讶。
- **码叔**：猫头鹰教授，每话结尾出来划重点。

## 剧情梗概

阿R 来到 Vue 餐厅后发现：这家店和自家完全不同——**菜是提前备好的**（编译器），**摆盘照着图纸来**（渲染器），**客人催菜靠摇铃**（响应式），铃一响只补变了的那盘菜。

## 分格解读

### 第 1 格 · 中央厨房（编译器）

模板字符串在**打包时**就被编译器预制成「半成品」（渲染函数），并贴好标签（PatchFlag、静态缓存）。运行时不用现场解析模板——这是 Vue 与 React 最大的路线分歧：React 把一切都留给运行时，Vue 把能提前算的都提前算（第 17 话详解编译器）。

### 第 2 格 · 前厅摆盘（渲染器）

render 函数跑一遍，产出 VNode 拼盘（虚拟 DOM 树），渲染器的 `patch` 拿新旧两盘对比，把差异端上真实餐桌（DOM）。阿V 端盘子上那些彩色圆球，就是标了 PatchFlag 的动态节点——运行时只盯着它们（第 13 话详解）。

### 第 3 格 · 传菜铃（响应式系统）

数据（Proxy 代理）一动，`trigger` 摇铃，订阅过这份数据的副作用函数（effect）被精准叫醒——**Push 式更新**。框架从源头就知道「谁变了、该更新谁」，不用像 React 那样整棵子树重算。套餐牌上的两种版本：完整版自带编译器（`vue.js`），工程构建用仅运行时版，更小更快。

## 码叔划重点

1. Vue 三大件：编译器（中央厨房）＋ 渲染器（前厅摆盘）＋ 响应式（传菜铃）。
2. Push 式更新：数据一动摇铃，精准通知订阅者，不必全单重算。
3. 工程里选 runtime-only 版本：模板已预编译，运行时不含编译器。

## 自测一题

**问：** 「Push 式」和 React 的「Pull 式」更新，最直观的差别是什么？

**答：** Push 式下，数据变化时框架从依赖关系里**精准知道**要更新哪些组件/节点（摇铃点名）；Pull 式下框架只知道「有更新发生了」，需要从触发点出发**重新计算**子树来得到新界面，所以 React 需要时间切片、Diff 这些手段来控制重算成本。

## 进阶追问

**问：** 既然中央厨房（编译器）这么香，为什么官方还保留仅运行时版本？两个版本在工程里怎么选？

**答：** 编译器的产物就是渲染函数，只要构建环节（如 Vite + `@vitejs/plugin-vue`）已经把 `.vue` 模板编译好，运行时根本不需要再带一份编译器，包体积更小、启动更快。因此工程默认用 `vue` 的 runtime-only ESM 入口；只有需要在浏览器里现场编译模板字符串的场景（如在线 playground、直接写 `template: '...'` 的 CDN 页面）才用完整版。第 17 话会拆解中央厨房内部的三段流水线。
