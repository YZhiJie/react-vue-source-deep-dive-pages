# 漫画 · 第 18 话 React vs Vue：两位厨师的做菜哲学

> 对应正文：[React vs Vue：两套顶级前端架构的正面对决](../../docs/comparison/react-vs-vue.md) ｜ 原画：[react-vs-vue.svg](./react-vs-vue.svg)

## 登场角色

- **阿R**：React 餐厅主厨，蓝色机器人。信条：订单来了就把整桌菜重算一遍。
- **阿V**：Vue 绿餐厅主厨，绿发少女。信条：记住每盘菜是谁订的，铃响只重做一盘。
- **码叔**：猫头鹰教授，终章出来主持擂台、宣布赛果。

## 剧情梗概

两位主厨把灶台并排摆开，正面比试三场：**更新哲学（Pull 对 Push）、优化方式（手动挡对自动挡）、适用场景**。比到最后码叔宣布：这是一场没有输家的擂台——而且两家正在互相偷师。

## 分格解读

### 第 1 格 · 两家灶台：Pull 对 Push

阿R 的厨房不记录「谁点了什么」，任何订单（setState）进来，都从触发点把整桌菜**重新算一遍**，再和旧桌 Diff 找不同——Pull 式，机制兜底，简单粗暴但可靠。阿V 的厨房用响应式依赖图记住每盘菜的订阅者，数据一变 `trigger` 摇铃，**只叫醒相关的 effect**——Push 式，精确追踪，读写拦截。

### 第 2 格 · 手动挡对自动挡：优化写在哪

阿R 把优化权交给开发者：`memo`、`useMemo`、`useCallback` 是手动挡杆，挂不挂挡你说了算；框架则把省下的精力投入运行时调度（Lane、时间切片、并发）。阿V 的车出厂即自动挡：编译器在打包时给动态节点贴好 PatchFlag、建好 Block，运行时按标签更新，开发者几乎不用手写优化。

### 第 3 格 · 没有输家的擂台

阿R 的「精密机床」擅长重交互、复杂并发、需要可中断渲染的场景（大屏、复杂编辑器、实时数据）；阿V 的「精准流水线」在表单密集、重约定、团队快速上手的场景里效率更高（中后台、管理系统）。而擂台中央写着：**两大范式正在互相靠近**——React Compiler 把编译期优化补回来，Vue Vapor 探索去 VNode 的更细粒度运行时。

## 码叔划重点

1. Pull 对 Push：React 被触发后整棵子树重算再 Diff；Vue 用依赖图精准定位更新源。
2. React 把「操作系统」搬进浏览器（Lane、时间切片、并发）；Vue 把「静态知识」交给编译器（Block、PatchFlag、静态缓存）。
3. React Compiler 与 Vue Vapor 都在吸收对方长处——选型看团队与场景，没有谁赢谁输。

## 自测一题

**问：** 既然 Vue 的 Push 式更新更「精准」，为什么 React 还要坚持 Pull 式重算？

**答：** 精准是有代价的：Push 式需要在每次读写时维护依赖关系（track/trigger、Dep/Link 链表），心智模型与内存开销都集中在框架侧；Pull 式放弃精确，换来的是机制极简——更新不需要知道谁变了，重算 + Diff 兜底即可，这也让「可中断、可丢弃、可重放」的并发渲染在同一套机制上自然成立。两种取舍没有绝对优劣：Vue 把复杂度交给编译器与响应式系统，React 把复杂度交给调度器，开发者的负担分布在不同位置。
